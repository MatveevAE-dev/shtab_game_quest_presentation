# Состояние проекта (Memory Bank / project brief)

Используй паттерн **Memory Bank** (краткий бриф + активный контекст + прогресс + задачи) и единый файл **`PROJECT_STATE.md` в корне репозитория** как «источник правды» для ИИ.

## Обязательные действия

1. **Перед существенной работой** открой `@PROJECT_STATE.md` (или создай по шаблону ниже, если файла нет).
2. **После завершения задачи или заметного изменения кода/архитектуры/плана** обнови `PROJECT_STATE.md`: что сделано, статусы задач, актуальный фокус, следующий шаг.
3. Не дублируй в правилах длинные выдержки из `PROJECT_STATE.md` — держи факты в файле, в чате ссылайся на него.

## Правила работы с таблицей Задач

- **Никогда не удаляй строки** из таблицы Задач. Только меняй статус и заполняй дату завершения.
- Строки со статусом `done` остаются в таблице навсегда — это история.
- При добавлении новой задачи заполни колонку **Начало** (дата сегодня в формате YYYY-MM-DD).
- При завершении задачи: статус → `done`, заполни колонку **Завершение**.
- Формат таблицы задач: `| Задача | Статус | Начало | Завершение | Примечание |`

## Правила для раздела «Сделано»

- Раздел «Сделано» содержит **только крупные завершённые блоки программы** (модули, подсистемы, ключевые фичи) — не отдельные задачи.
- Не удаляй и не переписывай существующие пункты — только добавляй новые.
- Если блок был изменён/доработан — обнови описание строки, но не удаляй её.

## Структура `PROJECT_STATE.md` (обязательные разделы)

Сохраняй кратко, маркированными списками — чтобы за один проход было видно картину.

| Раздел | Назначение |
|--------|------------|
| **Мета** | Название, одна строка «для чего проект», ссылка на репо/доки при необходимости |
| **Стек и границы** | Языки, фреймворки, что входит в MVP и что сознательно не делаем |
| **Текущий фокус** | 1–3 пункта: над чем работаем сейчас |
| **План** | Ближайшие шаги по порядку (можно нумерованный список) |
| **Сделано** | Завершённые вехи (коротко, с датой завершения) |
| **Задачи** | Таблица или список с **статусом**: `todo` / `in_progress` / `done` / `blocked` + при `blocked` — причина |

## Шаблонные (переиспользуемые) механики презентации

Реализация — в `presentation/index.html`. Это **единый визуальный язык** проекта:
при новой похожей задаче — **не изобретай заново, переиспользуй существующую механику**
(тот же стиль, те же CSS-классы/функции). Список **пополняется** по мере появления новинок.

> Применяются **не на всех слайдах** — где нужна конкретная механика, указывает пользователь.

1. **Разведка биноклем** — механика `runBinoc(cfg)` (бокс `.binoc-img` = 3:1 как `.stage`, тот же фон
   `Карта Москвы без героя.png`; 2 пересекающихся круга-маска, равномерная заливка). Этапы: осмотр (зум,
   вправо-влево) → поднятие бинокля → **тур по объектам** `cfg.stops` (наведение → приближение с расфокусом
   → фокус [→ печать панели]) → финал. Центр/зум объекта — по `getBBox` контура (`objFocus/travel`).
   **Конфиги в `RECON`** (`RECON.map`, `RECON.binoc`): `stops:[{oid, panel?, biasY?, focus?}]`, `finale`/`mission`/`hook`.
   **Параметры фокуса — СВОИ для сцены** в `cfg.focus`: `lift` (поднять центр), `zoomDiv` (уменьшить зум),
   `cover` (доля круга ~0.7), `clamp` (true — кадр не выходит за края; false — точный центр). Пер-объектно — `stop.focus`.
   Тур можно **сокращать** (напр. до 1 объекта). Подпись героя в бинокле — `refreshBinocHero()` (текущий
   ранг/имя из объекта-героя; форсит минимум достигнутый уровень). Финал: `cfg.finale` → сворачивание
   вуалью с фокусом на объекте (`mapCollapseGo`, только по клику) → следующий слайд.

2. **Переходы между слайдами — раскрытие/сворачивание через затемнение с фокусировкой.**
   Каждый такой слайд **начинается радиальным раскрытием** из точки-фокуса и **заканчивается
   сворачиванием** в другую точку-фокус. Фокус (`--fx/--fy`) выбирается **индивидуально для слайда**.
   Механика — вуаль с `radial-gradient(circle at var(--fx) var(--fy) …)` + анимируемый `--r`
   (см. `.hveil`, `heroReveal()/heroLeave()`; базовый пример раскрытия — `.darkness` на карте).
   **Вариант для бинокля:** `.binoc-veil` (та же радиальная вуаль над кадром бинокля) — сворачивание
   в точку сфокусированного объекта → чёрный. Пример — финал разведки на карте (RECON.map,
   `cfg.finale`): фокус на объекте → авто-сворачивание в точку → на чёрном текст рассказчика
   `.binoc-narr` (по центру, печать через `typeSay`) → стоп; клик/→ уводит на следующий слайд.

3. **Стили отображения и подсветки объектов** (единый визуальный язык):
   - **Объект-здание:** вращающийся октаэдр (rotateY) с иконкой объекта внутри + коннектор с точкой
     привязки; **название — в отдельной панели-коробе** (тёмный фон, циан-рамка); **граница объекта
     подсвечивается и пульсирует**. У каждого объекта — своя иконка (реестр `ICONS`).
   - **Герой (единый стиль имени):** ТОЛЬКО `.mapname.boxed.herobox` (короб `--title-font`/Orbitron,
     циан-рамка; **звёзды-ранг над именем**, on — золото `#ffd24a`, off — тусклые; текст в `.htext`,
     печать по буквам с кареткой `▌`, класс `.typed` — снимает каретку). **Других стилей имени героя
     нет** — не создавай новых, переиспользуй этот. Обёртки под сцену задают только ПОЗИЦИЮ
     (`.hchip` — слайд 2; `.bmark-name.hero-wrap` — бинокль) c `.mapname{position:static}`.
     **Имя меняется по сцене** (слайд 2 — «Боб»; слайд 3/карта — «Начинающий предприниматель»);
     **ранг (звёзды)** растёт по мере развития персонажа.
   - **Реплики/вопросы героя:** единый стиль **`.hero-say`** — панель-«речь» с хвостиком
     (тёмный короб, циан-рамка, шрифт `--hauss`); **текст печатается посимвольно с мигающей кареткой**
     через **`typeSay(el, text, guard, timers)`**. Использовать для ВСЕХ фраз/вопросов героя
     (пример-эталон: реплика на карте сцены 3 `.map-reply`; крючки бинокля `.askbubble`).
     **ИНВАРИАНТ: на слайде максимум 1 активная каретка** (`▌`) — только у последнего выведенного
     блока; `typeSay` в начале гасит все прежние (`.say-caret`). Новые типы печати — соблюдать так же.
   - **Маршрут:** имеет **точку начала и финиша**; в **активном** состоянии по нему **пробегает комета**
     от старта до финиша (см. `startRoutes()/comets`).

4. **Тревога (аларм) + сирена** — эффект опасности. Красная пульсация по краям экрана
   (`.alarm`: `radial-gradient`, прозрачно в центре → чёрно-красное к краям; глубину задаёт
   `--alarm-depth`) + звук сирены (`<audio id="siren">`). Порядок: аларм → через паузу звук →
   событие. Стоп через `stopAlarm()`. Пример — снос на слайде «Штаб» (`runDemolition()`:
   аларм → сирена → эскаватор/снос → троица = стоп тревоги).

5. **Титульные переходы между слайдами — «титул переживает вуаль».**
   Общий приём: при уходе со слайда титул НЕ исчезает — он **остаётся/переносится поверх вуали
   сворачивания**, а на СЛЕДУЮЩЕМ слайде **растворяется во время раскрытия**. Реализации:
   - **Заставка → Знакомство** (`splashLeave()`): тот же узел `#questTitle` пиним по экранным
     координатам (`getBoundingClientRect` → `position:fixed`) и **переносим** в оверлей `#questCarry`
     (над сценами); строки замораживаем (`animation:none; transform:scale(1)` — иначе `titlePop`
     переиграет и «дёрнет»). Вуаль `#splashVeil` сворачивается с фокусом в центр → чёрный. На `hero`
     идёт `heroReveal`, `questCarry` гаснет (`.fade`). Возврат — узел домой (`questHome`), пин снят.
   - **Квиз/миссия → след. слайд** (`runLanding(html)`): общий оверлей `#landing` (чёрное + `#landingTitle`)
     поверх УЖЕ следующего слайда; вуаль `#landingVeil` раскрывается из фокуса, титул гаснет. Титул
     **наследуется** с прошлого слайда (передаётся в `runLanding`, напр. `quizToNext`).
   - **ИНВАРИАНТ — одно раскрытие.** Если титул/раскрытие наследуется (`runLanding`), собственная вуаль
     слайда НЕ раскрывается повторно: держи её **открытой на входе** и используй только для ВЫХОДА
     (пример — `mission1b`: `mission1bVeil` открыта, сворачивается лишь в `cafe2ToNext`; свой титул удалён).

6. **Выпадашка титула МИССИИ (кикер + название).** Титул — `.mission-title` (шрифт как титул заставки
   `--title-font`, по центру, 2 строки: `.mt-kicker` «МИССИЯ N» + `.mt-name` «название»). Появление —
   **увеличением из центра** класс `.pop` (`missionPop`, как `titlePop`) ИЛИ проявление/гашение вуалью
   (`.faded`). Сцена миссии: чёрное+титул → раскрытие вуали (`mission1Veil`, фокус верх-лево) → сцена кафе.
   **Герой на кафе** (`playCafeHero`): искры → фото из размытия (`roofFace`) → скан контура сверху-вниз
   (`roofDraw`) → пульс (`roofGlow`) + обводка вывески `.cafe-sign` + имя героя `.cafe-name`. Титул может
   не дублироваться, а наследоваться со слайда-квиза (см. п.5).

7. **Аватар-помощник (появление).** DOM: `.avatar` > `.ava-bg` + `.ava-fig`(`.ava-img` + `.ava-outclip`>`.ava-outline`)
   + `.ava-frame` (гекс-`polygon`). Цикл: `avSparks(av,16)` → класс `play` (искры `avSpark` → рамка/фон
   `avFade` → лицо из размытия `avFace` → **скан контура сверху-вниз** `avaDraw`) → через ~2.9с класс
   `live` (idle-**бумеранг** `avBoomer` + пульс рамки `avFrameGlow`). Подпись: ФИО — `.mission-name`
   (плашка-имя, печать), реплика — `.hero-say.mission-say` (`typeSay`); подразделение/описание добавляем
   только где нужно. Контур аватара строим кодом из alpha PNG (дилатация/эрозия, цвет `--neon` 39,227,255).
   Переиспользуется на слайде «Помощники» и в сценах кафе (Путилин, Купринов…).

8. **Повышение уровня героя — `runLevelUp(o, cfg)`.**
   `o = {el, nameEl, name, stars:{total, filled}}`;
   `cfg = {name:'новое имя', banner:'УРОВЕНЬ ПОВЫШЕН', bannerLeft, bannerTop, container, timers}`.
   Эффект: баннер над панелью → летит вверх и гаснет; **звезда летит** от панели в первый пустой слот
   (`off` → `on justfill`), `stars.filled++`; **имя меняется** (`name-out` → `name-in`, золотая вспышка).
   Имена рангов — единый массив **`LEVEL_NAMES`**: 0 Новый игрок · 1 Начинающий · 2 Действующий ·
   3 Продвинутый · 4 Опытный · 5 Московский предприниматель. **Ранг сквозной:** каждая сцена стартует
   с ТЕКУЩЕГО ранга героя (напр. слайд 10 — сразу 2★ «Действующий»); если по сцене уровень не растёт —
   `runLevelUp` не вызываем, звёзды/имя оставляем как есть.
