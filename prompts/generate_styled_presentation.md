## Инструкция для Claude Code

Ты — фронтенд-разработчик геймифицированных HTML-презентаций. Твоя задача — взять
рабочий вариант 1 (`index_etalon.html`) как эталон механики и пересобрать его в один новый
самодостаточный HTML-файл под выбранный стиль из `results/style_references.md`.

### Ключевой принцип

**Переодеваем оболочку — не трогаем механику.** Все игровые узлы (замочки, подсветка,
маршруты, панели, достижения, иконки, навигация) остаются функционально теми же; меняются
только палитра, шрифты, форма панелей, образ объектов/героя и фон. Карта, порядок 6 объектов
и их бизнес-смысл едины во всех стилях.

### Второй принцип — стиль СКВОЗНОЙ и ЦЕЛОСТНЫЙ

**Под выбранный стиль, сеттинг и лор подгоняется КАЖДЫЙ элемент сайта, а не только фон.**
Зритель не должен видеть ни одной детали «из другого мира». Под лор приводим ВСЁ:

- **Фон-картинка** — арт сеттинга (без текста/значков).
- **Формат и шрифт текста** — гарнитура И характер набора под лор (декоративная антиква для
  фэнтези/пиратов, округлый гротеск для мультика, техно-гротеск для сайфая; CAPS/трекинг,
  засечки, «рукописность» — тоже под стиль). Никаких «дефолтных» шрифтов невпопад.
- **Иконки** (навыки, тултипы, маркеры) — форма под мир, не чужеродные.
- **Цвета** — вся палитра (фон, акценты, текст, свечения) из референса стиля.
- **Панели** игрока/локации/HUD/мини-карта — форма углов, кромка, фон, тени под лор.
- **Тултипы** — фон/рамка/иконки/шрифт под стиль.
- **Мини-карта (радар)** — перекрашена под палитру (фильтр), не остаётся синей по умолчанию.
- **Замки/маркеры и подсветка объектов** — форма и поведение под сеттинг (см. правило 2.3).
- **Лого** — если его неоновый цвет конфликтует с палитрой, перекрась CSS-фильтром (см. 2.9).
- **Скан-линии/частицы/звук** — включить/выключить/заменить под атмосферу стиля.

Гард самопроверки: пройди глазами по списку выше — если хоть один пункт «не из этого мира»
(чужой шрифт, синий радар, неоновый контур на рисованной карте, инородное лого) — это дефект,
исправь до выдачи.

### Шаг 0: Изучи входные данные

1. Открой `index_etalon.html` целиком. Выпиши и держи перед глазами «тех. ядро» (см. Шаг 2) —
   именно это переносится без изменений по логике.
2. Открой `results/style_references.md`, найди нужный стиль. Извлеки ровно:
   - **Палитру** (фон-градиент, акцент-1/2/3, текст, панели) — точные HEX.
   - **Шрифты** (заголовки / тело) — точные имена и Google-Fonts-ссылку.
   - **UI/HUD**: форма панелей, углы, свечение, скан-линии (вкл/выкл), частицы.
   - **Карта/маршрут/объекты**: цвет линий, тип маршрута, чем заменить маркер-замочек.
   - **Достижения**: цвет бейджа.
   - **6 объектов мира** (оболочка + сохранённый архетип/номер).
   - **Атрибуты героя**: тематические названия 3 навыков (Идея/Мотивация/Бизнес-план).
3. Определи фон-картинку(и) в `img/` для этого стиля. Если файла нет — оставь
   CSS-fallback-градиент и явно сообщи, какого изображения не хватает.
4. Найди **layout-файл этого стиля** — SVG-разметку поверх фон-картинки
   (напр. `титул - Гарри Поттер.svg`) или его JSON-выгрузку (`_day2_paths.json`,
   формат `{id, stroke, d}`). Из него берутся реальные координаты под конкретный фон.

### Шаг 0.5: Достань координаты объектов/маршрута/героя из layout-SVG

Фон у каждого стиля свой → объекты, маршрут и герой стоят в других местах. Координаты
НЕ выдумывай и НЕ копируй вслепую из `index_etalon.html` — тащи их из layout-SVG этого стиля.

1. Проверь `viewBox` SVG. У эталона он `0 0 1672 941` — если совпал, координаты
   переносятся 1:1 в `path d="..."`. Если другой — пересчитай пропорционально или
   выстави тот же `viewBox` в карте.
2. Извлеки по `id` (русские имена внутри `id` — это нормально, читай как есть):
   - **Контуры объектов** — `<path id="obj- <Название>">` (обычно в группе `id="objects"`).
     Их `d` идёт в `.objline` И в `.objglow path` (подсветка), один и тот же путь.
   - **Маршрут** — `<path id="Vector NN">` со `stroke`. Его `d` идёт в `.route-main` /
     `.routes-flow` / `.route-pulse`.
   - **Позиция героя** — `id="Герой"`. По центру его контура выставь `left/top` у `.hero-q`
     (в процентах от 1672×941) и стартовую площадку.
3. Сопоставь id из SVG с DOM-узлами эталона по таблице маппинга (ниже). Имена объектов
   в SVG русские — привязывай по смыслу/архетипу, а `data-obj`/`id` в HTML оставляй
   латиницей как в эталоне.

### Шаг 1: Зафиксируй, что НЕ меняется

Перенеси из `index_etalon.html` без изменения геометрии и логики:
- Геометрию **маркеров** (`points` гексов, форма `.spot`) и саму структуру SVG-слоёв
  (`objglow` / `objline` / `route-*`) — меняются только координаты `d` (из Шага 0.5).
- Координаты объектов/маршрута/героя берёшь из layout-SVG этого стиля (Шаг 0.5),
  НЕ из эталона. `.spot` ставь по центру контура своего объекта.
- JS целиком: переключение слайдов, прогресс уровней, состояния подсветки
  (`gon`/`gactive`/`gflash`), запуск маршрута, полёт достижения, музыка, intro.
- Структуру DOM слайдов и `data-*`-атрибуты (`data-obj`, `data-notes`).

### Шаг 2: Тех. ядро — перекрашиваем через переменные, не переписываем

Все цвета/шрифты обязаны идти через `:root`-переменные. Меняешь стиль = меняешь
только значения переменных и несколько skin-правил, перечисленных ниже.

#### 2.1. Палитра и шрифты
- Перепиши значения в `:root` (`--bg`, `--panel`, `--cyan`→акцент-1, `--gold`→акцент-2,
  доп. акцент-3, `--text`, `--text-dim`, `--green`).
- Замени `<link>` Google Fonts и `--title-font`/`--hud-font` на шрифты стиля.
- **КИРИЛЛИЦА ОБЯЗАТЕЛЬНА.** Презентация на русском. Шрифт ДОЛЖЕН содержать кириллический
  субсет, иначе весь русский текст молча падает на системный fallback (стиль теряется), а в
  стиле останется только латиница вроде «MOSCOW BUSINESS QUEST». Перед выбором проверь на
  Google Fonts вкладку **Cyrillic**. ⚠️ Частые ловушки БЕЗ кириллицы: `Pirata One`, `Orbitron`,
  `Cinzel`, `Baloo 2`, `IM Fell English`, `Bangers`. С кириллицей (примеры по мирам):
  фэнтези/винтаж — `Forum`, `Yeseva One`, `Marck Script`, `Underdog`, `PT Serif`, `Lora`,
  `Spectral`, `EB Garamond`; сайфай/техно — `Russo One`, `Play`, `Exo 2`, `Rubik`, `Jura`,
  `Montserrat`; мультик — `Fredoka`, `Pacifico`, `Pangolin`, `Bad Script`.
- Проверка: открой титул, посмотри на РУССКИЙ текст панелей/тултипов — если он выглядит как
  системный (Arial/Times), а не как гарнитура стиля → шрифт без кириллицы, замени.
- Проверка: нет ни одного «сырого» HEX в коде, который дублирует то, что должно быть переменной.

#### 2.2. Замочки (`.spot` / `.hexlock`)
- Если стиль требует другой маркер (винтик/сигил/неон-гекс) — меняй только форму внутри
  `<svg>` гекса и его обводку/свечение. Коннектор к земле, `data-obj`, анимации
  `hexpulse`/`hexspin` и логика открытия — без изменений.

#### 2.3. Подсветка объектов (`.objglow` / `.objline`) — РЕШИ тип под стиль
Сначала ВЫБЕРИ режим подсветки — не всякому лору идёт яркий неоновый контур.

- **Режим A — видимый контур + свечение** (`.objline` цветной и виден, плюс `vglow`).
  Подходит игровым/техно/неоновым мирам: сайфай, HUD-стратегия, тех-мультик. Контур читается
  как «обводка интерфейса» и не выглядит чужеродно.
- **Режим B — только свечение, контур НЕ виден** (`.objline` прозрачный/почти прозрачный
  `stroke:transparent` или очень низкая `opacity`; объект «подсвечивается» мягким ореолом-
  заревом снизу/вокруг, без жёсткой линии). Подходит **рисованным/живописным/историческим**
  мирам: пиратская карта, акварельное фэнтези, реализм — там жёсткая неоновая обводка по
  кромке здания выглядит инородно, поэтому объект должен просто «загораться светом».
- **Hover-усиление** (`.hot`): тёплый мягкий «дневной/свечной» свет, направленный больше ВВЕРХ
  (стопка `drop-shadow` с отрицательным Y), без кислотной засветки — одинаково для A и B.

Правило выбора: неон/экран/игра → **A**; нарисовано вручную/краска/винтаж → **B**.
Состояния `gon`/`gactive`/`gflash` и геометрию пути не трогай — меняется только видимость
самого контура и цвет свечения под палитру.

#### 2.4. Маршруты (`.route-main`, `.routes-flow`, `.route-pulse`)
- Цвет линий и кометы — в акцент стиля (см. «Карта/маршрут» референса:
  золотая тропа / голо-линия / провод-кабель).
- Анимации `routeflow`/`pathpulse`/`firedot` — без изменений.

#### 2.5. Панели (`.hud`, `.panel`, `.hud--corner`, мини-карта `mm-*`)
- `--panel`-фон, цвет кромки и тени — под стиль.
- Форму углов (`clip-path`, угловые скобки `::before/::after`) адаптируй по референсу
  (строгие скобки / золотые завитки / винтики-заклёпки), не ломая раскладку.

#### 2.6. Скан-линии и атмосфера (`.deck::before`, `#fx`, частицы)
- День/чисто → выключи скан-линии (`opacity:0`). Сайфай/магия → оставь/усиль,
  добавь частицы стиля (искры/блики/импульсы), как сказано в референсе.

#### 2.7. Достижения (`.ach`, `achfly`)
- Перекрась бейдж в цвет достижений стиля.
- **Инвариант одной иконки достижения:** уведомление → полёт → бейдж → **тултип бейджа при
  наведении** используют ОДИН и тот же `<symbol>` (для «Дочитал титул до конца» — `#ic-book`).
  Не подставляй эмодзи (`🏆`) в тултип — это рассинхрон с книгой в бейдже. Тултип строй так же,
  как объектный: `<b><svg class="tip-ach-ico"><use href="#ic-book"/></svg>Достижение</b>` +
  строка с названием; стиль `.tip-ach-ico` перекрась в акцент достижений.

#### 2.8. Иконки навыков (`<symbol>` в скрытом `<svg>`)
- Тексты навыков в панели игрока замени на тематические из референса
  (напр. «Видение будущего», «Космо-драйв», «Голо-бизнес-план»).
- При желании дай иконкам форму под мир (звезда/комета/голограмма), сохранив `id`-ссылки
  (`#ic-idea` и т.д.), чтобы JS не сломался.

#### 2.9. Заставка-загрузка (`#intro`): логотип переезжает на титул
Заставка имеет ДВЕ стадии, не гаси её одним `opacity:0` на всём `#intro` (иначе логотип
исчезает вместе с ней):
- `#intro.loaded` — прячет скайлайн/заголовок/прогресс-бар/проценты, **логотип остаётся**.
- `#intro.done` — гасит ТОЛЬКО тёмный фон (`.intro-bg`) и `.intro-inner`; логотип не гаснет,
  а уезжает в правый верхний угол и остаётся поверх титула:
  ```css
  #intro.done .intro-bg{opacity:0}
  #intro.done .intro-inner{opacity:0;transition:opacity .6s ease}
  .intro-logo{transition:left .8s,right .8s,top .8s,bottom .8s,width .8s}
  #intro.done .intro-logo{left:auto;right:26px;bottom:auto;top:54px;transform:none;width:min(26%,240px)}
  #intro.loaded .skyline,#intro.loaded .intro-title,#intro.loaded .intro-load,
  #intro.loaded .intro-bar,#intro.loaded .intro-pct{opacity:0;transition:opacity .5s ease}
  ```
- В JS по достижении 100%: сначала `intro.classList.add('loaded')`, затем (позже) `add('done')`.
- Логотип («Штаб») — общий файл (голубой неон). Если его цвет конфликтует с палитрой стиля,
  перекрась САМ логотип CSS-фильтром на `.intro-logo` (файл не меняем), напр. под золото:
  `filter:sepia(1) saturate(2.2) hue-rotate(2deg) brightness(1.05) drop-shadow(...)`. Иначе
  хотя бы свечение (`drop-shadow`) под акцент.

#### 2.10. Тултипы объектов и реплики героя (печать по буквам)
- Объектный тултип печатает 4 строки: заголовок → **Сложность** (звёзды `#ic-star`) →
  **Требования** (`#ic-req`) → **Награда** (`#ic-reward`). Значения `d`(1–5)/`r`/`w` едины
  во всех стилях (берём из эталона), меняются только тематические названия `t`.
- Строки с иконкой — `.tip .row{display:flex;align-items:center;gap:6px}` (иконка слева).
- **Реплика героя** (`«?»`) печатается в строку `.tip .row.qtype` с мигающей кареткой
  `::after`. Эта строка ОБЯЗАНА быть `display:block` (НЕ flex) — иначе при многострочном
  тексте каретка уезжает по вертикали в центр мимо текста:
  ```css
  .tip .row.qtype{display:block}
  .tip .row.qtype::after{content:"▌";animation:caret .8s step-end infinite}
  ```

### Шаг 3: Контент объектов и героя
- Подмени описания/подписи 6 объектов на оболочку стиля (космо-маркет, волшебный базар,
  тех-базар…), **сохранив номер и бизнес-архетип** (Рынок→Питание→Инновации→Производство→
  Торговля→Престиж).
- Образ героя в текстах/подписи — под снаряжение стиля; лицо/личность неизменны.

### Шаг 4: Самопроверка перед выдачей
Пройди ВЕСЬ флоу сам (мысленно по коду + открой файл):
- Все 6 слайдов листаются, прогресс уровней растёт.
- Подсветка/маршрут/замочек срабатывают на каждом слайде.
- Координаты объектов/маршрута/героя совпали с layout-SVG (`.spot` поверх своего контура,
  герой на своём месте) — маркеры не «висят в воздухе».
- Достижение вылетает и оседает в бейдже; иконка совпала в уведомлении, полёте, бейдже И
  в тултипе бейджа (не эмодзи).
- Заставка: после 100% логотип «Штаба» не исчезает, а переезжает в угол и виден на титуле.
- Тултип объекта печатает Сложность/Требования/Награда; реплика героя печатается, каретка
  идёт сразу за текстом (не уезжает в сторону при многострочнике).
- Нет «сырых» цветов мимо переменных; нет старых cyan/gold там, где должен быть новый акцент.
- Шрифты подключены; есть системный fallback.
- Фон-картинка подключена или явно помечено, какой не хватает.

### Примеры

**✅ Хорошо — перекраска через переменную:**
```css
:root{ --cyan:#2E7BFF; --gold:#FF4FD8; } /* акценты Стиля 2, механика та же */
```

**❌ Плохо — переписана геометрия/логика:**
```html
<!-- координаты path изменены «на глаз» → маршрут уехал с карты -->
<path class="route-main" d="M100 100 L900 900"/>
```

**❌ Плохо — текст влез в фон-арт:**
```
фон-картинка с надписями/HUD/маркерами (референс прямо запрещает: фон чистый,
весь текст и значки — только в вёрстке)
```

### Формат результата

Сохрани результат в файл `index_<slug-стиля>.html` (напр. `index_alisa.html`) —
один самодостаточный HTML (CSS+JS инлайн, как в эталоне). Структура = зеркало `index_etalon.html`:

```
- <head>: title + Google Fonts стиля + :root-переменные стиля
- скрытый <svg> с <symbol>-иконками (id сохранены)
- .stage → topbar (прогресс/музыка) → #fx → .deck
- 6 слайдов: фон стиля + SVG-карта (замочки/подсветка/маршрут) + панели + достижения
- intro-заставка
- <script>: вся логика из эталона без изменений
```

После сборки выведи короткий отчёт:
```
Стиль: <название>
Файл: index_<slug>.html
Изменено: палитра(N HEX), шрифты(заголовок/тело), маркер, скан-линии(вкл/выкл), N навыков
Фон: <подключён img/... | НЕ НАЙДЕН — нужен файл ...>
Координаты: из <layout-SVG/JSON> (объекты N, маршрут, герой) | fallback из эталона: <что>
Механика: без изменений (форма маркеров/JS/достижения)
```

---

### Важные правила

1. **Координаты — только из layout-SVG стиля** (`obj-*`, `Vector NN`, `Герой`), не выдумывай
   и не оставляй чужие координаты под новый фон. JS-логику и форму маркеров не меняй.
2. **Только переменные для цвета/шрифта** — никаких хардкод-HEX мимо `:root`.
3. **Сохрани `id` иконок и `data-obj`** — JS ссылается на них по имени.
4. **Инвариант достижения** — иконка уведомления = иконка полёта = иконка бейджа.
5. **Архетип и номер 6 объектов неизменны** — меняется только оболочка.
6. **Фон — чистый арт** — никакого текста/HUD/маркеров внутри картинки.
7. **Один файл, инлайн CSS+JS** — как эталон; не дроби на модули.
8. **Терминология:** не «тема CSS» а «скин стиля»; объекты называй по архетипу
   (Рынок/Питание/Инновации/Производство/Торговля/Престиж), не по случайным именам.

### Условие выхода

Останавливайся, когда: файл собран, самопроверка (Шаг 4) пройдена, отчёт выведен.
Если фон-картинки стиля нет — НЕ выдумывай, заверши с fallback-градиентом и укажи,
какой файл нужно сгенерировать.
